# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

A Godot 4.7 (Forward Plus) single-player tile-placement/economy game. There is no build step, no package manager, and no automated test suite — this is a GDScript project run and iterated on inside the Godot editor.

Code comments and in-game text are written in Turkish; keep new comments/UI text consistent with that unless the user says otherwise. In player-facing text a board piece is a **karo**, never "tile" — the English word was removed from every string the player can read (relic descriptions, tutorial steps, the money log). Code identifiers (`TileDef`, `TileCell`, `tile_generator.gd`) keep the English name.

## Running the project

Open and run from the Godot 4.7 editor (`project.godot` at repo root), or from the command line if the `godot` executable is on PATH:

```
godot --path . 
```

The main scene is `scenes/main.tscn` (configured via `run/main_scene` in `project.godot`), and it is the **only** scene. The start menu is a `CanvasLayer` overlay inside it, not a separate scene — deliberately, so that running the project (F5) and running the current scene (F6, which ignores `run/main_scene`) both show the menu first. Don't move the menu back into its own scene. There are no lint/test/build commands in this repo — verify changes by running the scene in-editor and playing through the flow described below.

## Architecture

The game splits cleanly into a data/logic layer (`scripts/data/`, no scene dependencies, `RefCounted`/`Resource` classes) and a UI/scene layer (`scripts/*_ui.gd`, `scenes/board_view.gd`, `TileCell`) that reads from and drives that layer. `scenes/board_view.gd` is the orchestrator that owns all game state and wires the UI panels together.

### Data/logic layer (`scripts/data/`)

- **`tile_data.gd`** (`class_name TileDef`, extends `Resource`) — a single tile: 4 edges (`Element` enum: `FIRE, WATER, EARTH, AIR, ETHER, VOID`), a `price`, and `placed_creature` (`Creature` enum: `SALAMANDER, ROC, GOLEM, ABZU, DAGON`, or `-1` if empty).
- **`board.gd`** (`class_name Board`) — owns the `ROWS x COLS` (8x5) grid of `TileDef` (or `null`). Key rules live here:
  - `edges_compatible(neighbor_edge, my_edge)` — the edge-matching rule is **directional/asymmetric**: `VOID` never matches anything except placing against an empty/off-board neighbor; `ETHER` matches anything; otherwise edges must match exactly.
  - `tile_fits(edges, row, col)` — checks all 4 neighbors for a candidate placement.
  - `_is_cell_accessible` / `get_expandable_cells` — a cell is placeable only if it has a filled neighbor with a non-`VOID` edge facing it.
  - The start tile (all `ETHER`) is placed at `grid[7][2]` (bottom-center) on init; the win cell is `grid[0][2]` (top-center, see `WIN_ROW`/`WIN_COL` in `board_view.gd`).
- **`tile_generator.gd`** (`class_name TileGenerator`) — weighted-random edge generation and price calculation (`compute_price(edges, row)`: a **per-row base** from `ROW_BASE_PRICE` (3 at the bottom start row up to 8 at the top win row), + one per ether edge, − discount for void-edge count). `generate_draft(row)` produces the 3-option draft shown to the player.
  - Edge weights are **per-row**, not global: `ROW_EDGE_WEIGHTS` is indexed by board row (0 = top/win row … 7 = bottom/start row). Going up, `ETHER` falls 30 → 9 and `VOID` rises 10 → 31 while the four real elements stay at 15 each, so climbing gets progressively harder. `_init()` asserts every row sums to 100 and that the table has `Board.ROWS` entries.
  - Creatures are **not** uniform random: they come from a depleting weighted pool (`CREATURE_POOL_SIZE` 20 of each, 100 in all, refilled per run because `board_view._ready` builds a new `TileGenerator`). A type's weight *is* its remaining count, so after five Abzus it is 15 against the others' 20 and a run never goes without seeing a type. 100 draws yield exactly 20 of each; when every allowed type is spent the pool refills, since a run generates roughly one pool's worth of cards.
    - `pick_random_creature(consume)` / `generate_draft(row, consume)` take a flag because three call sites are **not** real drafts: the stuck-check in `_check_stuck_after_creature` passes `false` (it is never shown, so it must not drain the pool — the same rule as `Karanlık Tohum`'s guarantee), while the `İleri Görüş` previews do consume, and `_refresh_foresight_preview` hands the creatures back with `return_creature()` when a preview is discarded unused. `Ortak Kan` draws **one** shared creature instead of one per card, and `Karanlık Tohum`'s forced Dagon returns the card's original creature before taking a Dagon, so the counts stay honest.
  - The tier follows **the row of the cell being placed into**, not the highest row reached — so `generate_edges`/`generate_draft_pair`/`generate_draft` all take a row, and `board_view` passes `pending_cell[0]` (both in `_show_draft_for_pending` and `_on_refresh_selected`). The one draft with no chosen cell is the stuck-check in `_check_stuck_after_creature`, which uses `_cheapest_open_row()` (the topmost expandable row, where tiles are cheapest) so the loss check errs in the player's favour.
  - The edge weights alone would make upper-row tiles *cheaper* on average (ether raises price, void discounts it) — measured 3.80 at the bottom row falling to 2.13 at the top. That is **not** wanted: climbing should cost more, so `ROW_BASE_PRICE` overrides the drift and the measured averages now climb 3.80 → 7.14.
  - When that curve changes, re-check `board_view._cheapest_open_row()`. It used to take the topmost expandable row on the assumption that up meant cheap; with per-row base prices that became the *most* expensive row and the stuck-check started erring against the player. It now reads `ROW_BASE_PRICE` directly instead of assuming a direction.
- **`creature_scorer.gd`** (`class_name CreatureScorer`) — pure scoring logic for each creature's payment rule when placed. Salamander and Roc **wrap at a cap** rather than growing forever (`SALAMANDER_MAX_PAIRS` 6, `ROC_MAX_GROUP` 8, both via `_wrap`): the 7th pair counts as the 1st again and a 9-Roc flock counts as 1, so a player has to keep starting new structures instead of inflating one. Payment and the progression threshold both read the wrapped value. The scoreboard deliberately does **not** show the second lap: `_payout_at` returns 0 past each cap (`_cap_for`) so those columns read `-`. Repeating the cycle's numbers there was tried and rejected — the column header is an achievement step, and there is no 7th pair, only a 1st one again (and, for Abzu, retroactively when neighbors are added later via `update_abzu_neighbors`). Each creature has a distinct spatial rule (symmetry, flood-fill group size, **farthest**-same-creature gap, 8-neighbor fill count, diagonal count). Salamander pays `3 * pair_count` (3, 6, 9, …). Golem pays the number of tiles *between* it and its **farthest** twin (`_farthest_same_creature_gap`, Manhattan distance − 1), so two adjacent Golems pay nothing. Dagon now also pays **retroactively** like Abzu: `update_dagon_neighbors` gives each existing Dagon the difference when a new one joins its neighbourhood, tracked per tile in `TileDef.dagon_last_count` — see the `CREATURE_DESCRIPTIONS` in `legend_ui.gd` for the player-facing summary of each.
- **`economy.gd`** (`class_name Economy`) — player money, spend/gain, and the loss condition (`can_afford_anything` across the current draft + refresh cost). Starting money is not a constant: `Economy.start_money()` = `BASE_START_MONEY` (15) + `Progression.get_starting_soul_bonus()`, applied in `_init()`.
- **`progression.gd`** (`class_name Progression`) — cross-run meta-progression, persisted in `user://progress.cfg`. See the section below.

### UI/scene layer

- **`scenes/board_view.gd`** (extends `GridContainer`, the `%GridContainer` node) — the central controller. Owns `Board`, `TileGenerator`, `CreatureScorer`, `Economy` instances and all turn-state flags (`is_drafting`, `is_pending_placement`, `placing_creature`, `pending_*`). Rebuilds the entire grid of `TileCell` nodes on every state change via `_render_board()` (no incremental diffing — the grid is fully torn down and recreated with `queue_free()`/`add_child()` each time). Connects to signals from the side panels rather than the panels reaching into board state directly.
- **`scripts/tile_cell.gd`** (`class_name TileCell`, extends `Control`) — a custom-drawn (`_draw()`) single grid cell. The seam feather between two edge regions is drawn as **triangles, never quads** (`_draw_seam_band`): the band's inner and outer rails are clamped to the cell rect, which near a corner can swap their order and turn the quad into a self-intersecting bowtie that `draw_polygon` cannot triangulate — it logged `Invalid polygon data, triangulation failed` on every frame. Two triangles cover the same area with the same vertex colours and cannot fold. `_draw_textured` additionally skips polygons that collapse to zero area, reused both for the actual 8x5 board and for small preview cards in the side panels (`cell_size` is configurable per instance). Visual states: empty/selectable (`+`), filled with edge-color strips + creature glyph, live placement preview (gold border), static/invalid preview (red border, used in draft cards), and a *buyable* draft card — `is_buyable`, the only state that tracks hover and draws a gold border under the cursor, kept separate from the board's own `is_selectable` so the board's visual language is untouched.
- `board_view._float_soul(row, col, amount)` — when a creature earns souls, the amount rises out of its own cell and fades away, drawn as a `SoulAmount` droplet like every other amount in the game. Retroactive payouts matter here: Abzu and Dagon pay *other* cells' creatures, so `CreatureScorer.last_extra_payments` reports a `[row, col, amount]` breakdown instead of a single total, and `_flush_extra_payment_souls()` floats one droplet per paying creature. A lone total would have had no cell to rise from.
- `board_view._flame_cell(row, col)` — a short ember-coloured flare over one cell, used when a Salamander pair completes, to show the two are linked. `_mark_flame(row, col, owner)` is the other half: when a Salamander has no partner yet, the cells where a partner could go get a **permanent** pulsing flame drawn with `UiTheme.FLAME_FRAME` (`assets/elements/alev_cerceve.png`, whose centre is fully transparent so the cell shows through). It is positioned by its **measured content**, not by a tuned scale factor: `UiTheme.flame_content_rect()` finds the artwork's visible bounds and `_flame_rect` sizes the texture so those bounds land exactly on the cell. This matters because the asset has been swapped several times and each version carried different, asymmetric transparent padding — a hardcoded multiplier needed re-tuning every time. The scan does **not** use `Image.get_used_rect()`: that counts any alpha above zero, and these textures have near-invisible stray pixels out to the canvas edge, which made it report the whole image. Instead the image is resized to `FLAME_SCAN_SIZE` (128, done engine-side) and scanned against `FLAME_ALPHA_THRESHOLD`; the result is cached and takes about 10 ms once. It is also translucent (`FLAME_ALPHA_LOW`/`HIGH`, the pulse range) so the tile and creature under it stay readable. Which cells depends on the relic: normally just the mirror cell in the same row, but with `İkiz Kor` the partner may sit in **any** row of the mirror column, so the whole column is marked — `CreatureScorer` decides this and reports a list. The two kinds also retire differently, which is what `owner` is for: a plain mark goes out when a tile is placed in its cell, while an `İkiz Kor` mark belongs to the Salamander that created it and goes out when *that* Salamander pairs — it must keep burning over cells that already hold a tile, since the partner can still be placed there later. `_update_flame_marks()` runs at the end of every `_render_board()` to retire the finished marks, and `board_view._process` re-fits the live ones to their cells every frame. They are placed from `_cell_rect()`, which reads the `TileCell`'s own rect rather than computing it: `_cell_center()` steps by `board_cell_size + separation` (100.5) while `GridContainer` actually lays cells out on integer positions (step 100), so the computed position drifted further the further down-right the cell was — up to 3.5px at the last cell, which is what made the frames look misaligned. `_cell_rect` still falls back to the computed value on the frame a cell is created, before layout has run. `CreatureScorer` only reports which cell (`last_salamander_flame`); the data layer never touches the scene. The effect lives in a temporary `Panel` parented to the scene root, not to the cell — `_render_board()` destroys every `TileCell` on each state change and would kill the tween.
- **`scripts/creature_icon.gd`** (`class_name CreatureIcon`) — small custom-drawn shape-per-creature icon, used in the legend.
- Side panels under `Root/Layout/SidePanels` in `scenes/main.tscn`, each a `PanelContainer` subclass communicating with `board_view.gd` purely via Godot signals (never called into directly by name for state changes):
  - `draft_ui.gd` (`DraftPanel`) — shows the 3-tile draft with per-option prices and fit validity; emits `pair_selected` / `refresh_selected`. There is **no separate buy button**: the card's `TileCell` is the button (`set_static(..., buyable)` makes it clickable, hover-highlighted and pointing-hand), and `buy_cards` holds the clickable ones. Since a disabled button no longer carries that information, the two reasons a card cannot be taken stay visually distinct: it does not fit → red border on the tile (`is_invalid`), you cannot afford it → the price is drawn in `SoulAmount.DENIED_TEXT` red (set via the `affordable` flag).
  - `placement_ui.gd` (`PlacementPanel`) — rotate/confirm UI for a tile pending placement; emits `rotate_requested` / `confirm_requested`.
  - `creature_ui.gd` (`CreaturePanel`) — prompts the player to place (or skip) the creature that came with the just-placed tile; emits `skip_requested`.
  - `end_game_ui.gd` (`EndGamePanel`) — win/lose screen with a restart button (`get_tree().reload_current_scene()`).
  - `legend_ui.gd` (`LegendPanel`) — static reference panel listing each creature's scoring rule.
  - `money_ui.gd` (`MoneyLabel`) — extends `SoulAmount`; polls `board_view.economy.money` every frame via `%GridContainer` and self-positions in the top-right corner.
- **`scripts/soul_amount.gd`** (`class_name SoulAmount`, extends `Control`) — the single way money is displayed: it draws `assets/ui/soul.png` and writes the amount inside the droplet. Two measured constants make it legible, so don't "simplify" them away: `UiTheme.SOUL_EMBLEM_REGION` crops the texture's large transparent glow padding (the emblem is only the middle ~57% of the 512px square, and the droplet itself only ~27%, so drawing the texture whole leaves the number spilling outside the droplet), and `DROPLET_CENTER` puts the number on the droplet's widest band rather than the texture's geometric centre. The number is drawn in Lobster (`assets/fonts/lobster.ttf`, SIL OFL), served by `UiTheme.soul_font()`. Sharp high-contrast serifs (Cinzel, Playfair Display) were tried and rejected — they clash with the droplet's soft curves. `soul_font()` deliberately `load()`s rather than `preload()`s and returns `null` when the file is not imported, so the script still compiles and `soul_amount.gd` falls back to the theme default font. Digits are drawn **one at a time, each centred in a fixed-width cell** (`_digit_cell`/`_draw_digits`), never as one `draw_string`: "1" is far narrower than the other digits in most faces, so a proportional string makes the number jump sideways inside the droplet every time it changes. Two more constants are measured from the font: `DIGIT_BOX_CENTER` (0.372 em, the vertical middle of Lobster's digit glyph box) sets the baseline so the digits' own body is centred — the font's ascent/descent box spans all letters and centres them wrong — and `MAX_TEXT_WIDTH` shrinks the size for three-digit amounts, which would otherwise spill past the droplet. The glyph sits under two outline passes that fake a glow in the droplet's own green (`GLOW_COLOR` wide and translucent, `HALO_COLOR` narrow and bright), since Godot's outline is a flat band rather than a blur; both minimum thicknesses are deliberately low because a 40px icon puts the text at 16px, where a thicker floor eats the digits. A white halo and a dark thickening outline were used before the font existed — white read as a sticker against the green. Every place that shows an amount uses it — draft card prices, the refresh cost, the top-right counter, the log rows — so don't render a bare number or a coin emoji anywhere. Note that the draft panel's icon sizes are capped: raising `PRICE_SOUL_RATIO`/`TITLE_SOUL_SIZE` pushes the panel past `UiTheme.ACTION_PANEL_HEIGHT`, which the three action panels share — and the panels set that height between them (measured content heights, frame included: creature 322, draft 275, placement 268) — the creature panel is the tallest since the buttons were restyled, so re-measure all three rather than assuming which one wins.
- `scripts/main.gd` — root node script of `scenes/main.tscn`. Adds the runtime-only overlays (`ForestAtmosphere`, `TutorialManager`) and hands the tutorial its node references, because `%UniqueName` lookups only resolve from nodes that belong to the scene — a node created at runtime cannot use them.
- **Panel frames** — three textures, one per shape: `PANEL_DRAFT` (`assets/ui/draft_paneli.png`, wide — the three action panels and the chooser's relic cards), `PANEL_LOG` (`log_paneli.png` — money log, scoreboard, foresight, tutorial box, toast) and `PANEL_LEGEND` (`yaratik_paneli.png`, tall — the legend panel and the full-screen modals). The names do not line up with the constants (`yaratik_paneli` is the *legend* frame), so go by `UiTheme`, not by the filename. The `.jpg` beside each is the **source as delivered**: the frame drawn on a black canvas (two of them on a white page), which as a texture would paint an opaque black box over the forest. The `.png` is that art with the black (and white) keyed out — alpha is a ramp on luma and the background is un-multiplied back out (`fg = observed / alpha`), leaving the vine frame with a see-through middle, which is what the whole panel system assumes. The sources stay in the repo and are kept out of the build by `exclude_filter` in `export_presets.cfg`. Each cutout is trimmed to its frame and resized to the **same dimensions as the frame it replaced** (306x148, 307x183, 310x478), because a nine-patch draws its corners at source pixel size: at the delivered 3072px the corner ornaments would have been drawn many times larger than the panels. Keeping the old size also keeps every `frame_stylebox(tex, margin, pad)` call site valid — the measured border thickness (9-19px) and inner opening (8-18px) match the old frames' 12-16 and 10-16. Re-measure both whenever the art is replaced.
- **Panel grounds (`UiTheme.art_backdrop`)** — the frame styleboxes are hollow nine-patches, so by default whatever is behind a panel shows straight through its middle, and small text over the forest art is unreadable. `art_backdrop(dim)` returns a `Control` holding the game's own forest art (`UiTheme.BACKGROUND`, cropped with `STRETCH_KEEP_ASPECT_COVERED`) under a night-navy `ColorRect`; add it to a container **before** the content so it sits underneath. The tutorial box and the scoreboard both use it, with their own dim values. Flat colour grounds were tried and rejected — the panel frames are teal and the forest is turquoise, so an invented green reads as olive and clashes.
- **Fonts (`UiTheme._register_fonts`, part of `apply_ui_theme`)** — two faces, both SIL OFL, licences beside them in `assets/fonts/`: **Marcellus** is the default `Label`/`RichTextLabel`/`TooltipLabel` font, for the long explanatory text the UI is mostly made of (creature rules, relic descriptions, tutorial narration); **Cinzel** (variable, bold via `wght` 700) is the `Button` font and the `NumberLabel` type variation, used for short "carved" text and numeric labels such as the scoreboard cells. They are registered on the same default theme as the button styleboxes, for the same reason — a theme on the scene's root Control never reaches the `CanvasLayer` screens.
  - The soul droplet's digits are **deliberately outside this**: they are Lobster and are drawn directly in `_draw` via `soul_font()`, so no theme font touches them. Sharp serifs were tried there and rejected.
  - The `add_theme_font_size_override` calls scattered through the UI scripts do **not** fight the theme — they set only the point size, not the family, and they are what builds the type hierarchy (title 56, subtitle 18, relic strip 14, …). Don't delete them when changing fonts.
- **Button look (part of `UiTheme.apply_ui_theme`)** — every text button in the game draws `assets/ui/button.png`, a 1921x582 pill with rounded caps and a leaf/flower ornament at each end. `BUTTON_SOURCE_CAP` (400) is the measured x where those ornaments end — re-measure it from the silhouette whenever the artwork is replaced, or the leaves will stretch. The art must be a PNG **with an alpha channel**: a version exported without one arrived with its checkerboard baked in as real pixels, and had to be keyed out by flood-filling the light neutral background from the border. `main.gd` calls `apply_ui_theme()` once on startup and it writes into **`ThemeDB.get_default_theme()`**, not into a `Window` or a `Control`: Godot breaks theme inheritance at any node that is neither `Control` nor `Window`, and this scene's root (`Main`) is a plain `Node` while the menu, tutorial, relic and progression screens each live on their own `CanvasLayer` — so a theme set on the window reaches nothing. The default theme reaches every Control regardless of where it sits. Like an autoload it survives `reload_current_scene()`, hence the `_theme_applied` guard.
  - The pill is a nine-patch (`StyleBoxTexture`) so the caps and ornaments do not stretch. **Godot draws nine-patch corners at their source pixel size and never scales them**, so the texture is first resized to the target button height and `BUTTON_SOURCE_CAP` is scaled by the same factor; skip that and a 42px button gets 400px-wide caps. The text's side padding is derived from the scaled cap (`side_extra` is the gap *past* the ornament), not given as a fixed number, so small buttons do not print their label over the leaves. States are opaque `modulate_color` tints, never alpha.
  - Three registered types: `Button` (42px), `SmallButton` (32px, used by the relic strip — full-size buttons there push the two-row strip over the nav buttons), and `IconButton` (empty styleboxes, used by the nav and rotate arrows). `IconButton` exists because `Button.flat` only skips *drawing* the stylebox — its content margins still apply, and the pill's padding squeezed a 64px icon down to 4px.
- `scripts/game_nav_ui.gd` (`GameNavButtons`) — the always-visible in-game `Ana Menü` button (icon-only: `UiTheme.BACK_ICON`, name **and shortcut** in the tooltip, which opens instantly because `project.godot` sets `gui/timers/tooltip_delay_sec` to 0), also bound to `Esc` — disabled while the tutorial runs or the relic modal is open. A `Yeniden Başla` button sat beside it and was removed: wiping a run mid-game was one careless click away, and its `R` shortcut now refreshes the draft instead. Restarting is the end-game panel's job, which is why the static `restart()` stays here. created by `main.gd` and aligned every frame to the top-left of the right column (the money counter holds the top-right). `BUTTON_SIZE` (64px) is part of a **fully booked vertical budget** in that column, so changing it means re-checking the whole chain: the buttons and the relic strip share the band above the action panels, and the strip is bottom-aligned to it, so `SidePanels/Spacer` in `main.tscn` (180px) must cover margin + buttons + gap + the strip's **largest** icon row + `RelicPanel.BAR_GAP`. Below that, the action-panel box must still end above the free-positioned money log (top at y 543 on the default 1400x820 viewport). The measured chain at 180: buttons end at y 88, an 88px strip runs 96–184, the panels start at 192 and their 340px box ends at 532, 11px above the log. That is where `RelicPanel.BAR_ICON_MAX` (88) comes from, and why the strip's stylebox has **zero** content margin — the padding is exactly what an 88px row cannot spare. The buttons were 48px and the strip drew straight over them before this was worked out. Its static `restart()` / `go_to_menu()` are the one implementation of both reloads; `end_game_ui.gd` calls them too.
- `scripts/credits_ui.gd` (`CreditsPanel`) — the menu's "Künye" screen, built on the same recipe as `ProgressionPanel` (own `CanvasLayer` above the menu, opaque backdrop, `UiTheme.art_backdrop` ground under the hollow frame). Its content is the `ENTRIES` table — one place to edit who is credited.
- `scripts/menu_overlay.gd` (`MenuOverlay`) — the start menu, a `CanvasLayer` over the game scene (title, `Oyna` / `Nasıl Oynanır` / `Çıkış`). `Nasıl Oynanır` does not open a text page: it emits `tutorial_requested`, and `main.gd` starts the hands-on tutorial. `MenuOverlay.skip_next` (static, survives `reload_current_scene()`) lets the end-game `Yeniden Başla` button reload straight into the game while `Ana Menü` reloads into the menu.

### Tutorial (`scripts/tutorial_manager.gd`)

A hands-on, step-gated tutorial rather than a text page. It **observes** the game and never drives it: `board_view.gd` emits `cell_selected` / `tile_purchased` / `tile_rotated` / `tile_placed` / `creature_placed`, and each step advances only on its own event, so the player has to actually make the move.

- `scripts/tutorial_overlay.gd` (`TutorialOverlay`) does the locking and highlighting in one node: it covers the screen, and `_has_point()` returns `false` inside the current step's target rects so clicks fall through to just those elements while every other click is silently swallowed. Everything outside the holes is dimmed, and the holes get a pulsing gold border. `_dim_rects()`/`_subtract()` exist because Godot cannot draw a rectangle with holes — the screen is split into the pieces that remain.
- Target rects are recomputed **every frame** (`_target_rects()`), not cached: `_render_board()` destroys and recreates every `TileCell`, so node references from a previous frame go stale. `board_view.cell_nodes` holds the current `"row,col" -> TileCell` mapping for this.
- Three of the ten steps are pure reading steps that advance on a `Devam` button instead of a game event, and add a block under the instruction text (`STEPS[...]["extra"]`, built once in `_build_ui`, only visibility toggled): `MATCH` explains edge matching, `SCOREBOARD` points at the score table (it is the step's only target rect, so the overlay leaves it lit while everything else stays dimmed) (a swatch per element — a mini `TileCell` with all four edges the same, so the player sees the real texture — plus the `MATCH_RULES` restating `Board.edges_compatible`), and `CREATURES` lists all five creatures with icon, name and payment rule. Both read their strings from the existing sources (`TileCell.ELEMENT_NAMES`, `LegendPanel.CREATURE_NAMES`/`CREATURE_DESCRIPTIONS`) — don't copy them here. Neither step opens a hole in the overlay, so the board stays locked while they read.
- The frame stylebox is hollow, so every step draws over `box_backdrop` — `UiTheme.art_backdrop(BOX_DIM_COLOR)`, added before the box and fitted to it every frame in `_layout_box`. The box is dimmed harder than other panels because it is small and its text dense; text over the bare dimmed board is unreadable otherwise.
- Step texts state only what is always true. The `MONEY` step points at the counter ("Ruhunu sağ üstteki damlanın içinde görebilirsin") and mentions that creature achievements permanently raise the next runs' starting souls (see the İlerleme screen), rather than announcing a payout: the tutorial's first creature usually satisfies no rule (Salamander waits for its symmetric partner, Golem for a second Golem) and pays nothing.
- Autowrapped labels in the box get their real width written every frame by `_fit_wrapping_text()`: Godot measures a wrapped label's minimum *height* from its minimum *width*, so without it the box is measured one line tall and the rest of the text spills outside the frame.
- Only the current step is shown — a `Adım 3 / 10 · <short name>` heading plus that step's instruction. Its width is derived at runtime from the board's own width (`BOX_WIDTH_MARGIN` wider, read from the `GridContainer`'s rect so the grid separations are included), and it is centred on the board rather than on the viewport — the side columns are not always equal, so viewport-centring would make the overhang lopsided. The box sits **top-centre**, over the board's top rows — fine while those rows are empty and dimmed, but the last step highlights exactly that area (the key cells and the top-centre win cell), so the box moves to the **top-right** for it. For that position the box must stay narrower than `UiTheme.COLUMN_WIDTH`: that keeps it inside the right panel column, and the board can never slide under it because `SidePanels` reserves at least that width.
- The rotate/confirm steps are skipped automatically when only one rotation fits (the game auto-places, `tile_placed` arrives while the tutorial is still on the rotate step).
- First run starts it automatically; `scripts/game_settings.gd` (`GameSettings`) persists `tutorial_completed` in `user://settings.cfg`. Both exits — `Bitir` on the last step and `Atla` at any point — mark it complete and reload the scene back to the menu, since the tutorial leaves a half-played board behind. The `game_over` path is the exception: it calls `_finish()` without reloading, so the end-game panel stays on screen.

### Keyboard controls

`board_view._unhandled_input` is the one place the board's keys live, and what a key means depends on the phase: with a tile pending placement `A`/`D` (or `←`/`→`) rotate and `Space` confirms; while the draft is open `A`/`S`/`D` (or `←`/`↓`/`→`) buy the first, second or third card and `F`/`↑` the fourth (only present with `Zaman Kumu`), routed through `DraftPanel.select_card` so only cards the mouse could click are reachable; otherwise the arrows/WASD move `key_cursor` between the cells that are currently clickable and `Space` activates it — expandable empty cells when idle, valid creature slots while placing a creature. `_cursor_candidates()` derives that list the same way `_render_board` does, so the keyboard can never do something the mouse cannot. `R` refreshes the draft while it is open, routed through `DraftPanel.press_refresh()` so it fires only when the button itself is enabled — the same rule as `select_card`, the keyboard can never do what the mouse cannot. (It used to restart the run from `game_nav_ui.gd`; that button is gone.) `TileCell.is_key_focus` draws the cursor, and it only ever appears once a direction key is pressed. The relic screen has the same scheme of its own (`relic_ui._unhandled_input`): `A`/`S`/`D`/`F`/`G` or the arrows pick the nth card, and it serves both the 3-card chooser and the contract sub-picker because both fill `_content_row` — `_make_clickable_frame` stores each frame's action in a `"action"` meta so the keyboard can invoke exactly what a click would. Board keys are ignored while that modal is up or the tutorial is running (`_keyboard_blocked`) — the tutorial gates on clicking the highlighted element, and a shortcut would walk straight through it. `Esc` is not handled here; it belongs to `game_nav_ui.gd`.

### Audio

`GameSettings` persists two independent switches in `user://settings.cfg`: music and sound effects. The menu shows them as small toggle buttons whose label carries the state. `MusicManager.apply_audio_settings()` starts or stops the ambient loop immediately so the change is audible without reloading, and both `MusicManager.play_oneshot` and `board_view._play_sfx` return early when effects are off — those two are the only paths that play a sound, so gating them covers everything. A draft card that cannot be taken still answers the click: `TileCell` is not selectable then, but `is_card` (set by `set_static`) makes it emit `rejected`, `DraftPanel` turns that into `card_rejected("fit"|"soul")` — it is the only node that knows why — and `board_view._on_card_rejected` plays `reject_fit.wav` or `reject_soul.wav`. The reason is **fit first** when both apply: souls would not help, the karo still does not go there. The keyboard path gives the same sound (`select_card` reports the rejection instead of silently returning false), and `_on_pair_selected`'s affordability guard plays the soul one too. Both go through `_play_sfx_path` (a path, not a `preload`), so an unimported file is skipped silently.

### Relic system (kalıntılar)

Collecting a key grants one relic chosen from 3 random options; a run has 4 keys → 4 relics. The relic pool and **all** relic effect logic live in one place: **`scripts/data/relic_manager.gd`**, registered as the `RelicManager` autoload (alongside `MusicManager`). It is a `Node` — the one data-layer file that isn't a scene-free `RefCounted` — because relic state must be global and single-instance. Every other system (`economy.gd`/`board.gd`/`creature_scorer.gd`/`tile_generator.gd`/`board_view.gd` and several `*_ui.gd`) only *asks* it (`has_relic`, `adjust_tile_price`, `keys_needed`, `salamander_pair_bonus`, …); never re-implement a relic condition outside this file.

- `scripts/data/relic.gd` (`class_name RelicDef`, `Resource`) — one relic: `id`, `display_name`, `description`, `category`, `one_shot`, `choice_kind` (`""`/`"creature"`/`"element"` — relics that pick a contract target on acquire).
- Autoloads survive `reload_current_scene()`, so `board_view._ready()` calls `RelicManager.reset()` each new game. The one turn-scoped counter (`Tüccar Yüzüğü`'s free refresh) resets via `RelicManager.begin_turn()` at the top of `_on_cell_pressed`.
- `scripts/relic_ui.gd` (`class_name RelicPanel`, `CanvasLayer`, created by `main.gd`, ref handed to `board_view`) is **one node, three jobs**: the modal 3-card chooser (full-screen backdrop locks the game until a pick), the contract/`Kılık Taşı` sub-picker (same modal), and the always-on owned-relics strip. Neither the chooser nor the sub-picker has a confirm button — the framed card *is* the control, the same pattern as the draft cards. `_make_clickable_frame()` builds it (pointing-hand cursor, `modulate` tint on hover, `gui_input` for the click) and both callers use it; the inner `VBoxContainer` is set to `MOUSE_FILTER_IGNORE` so it does not swallow the click. The bar is added before the modal so the backdrop covers it. The strip sits **directly above the action-panel box** (draft/placement/creature), the same width as the right column, laid out left-to-right in an `HFlowContainer` — bottom-left was taken by `ScoreboardPanel` and the two overlapped, and docking the bar inside `LeftPanels` pushed the other panels around, so it stays free-positioned and is aligned every frame in `_process` (the money-log approach): `main.gd` hands it `bar_anchor = %DraftPanel.get_parent()` (the always-visible `SidePanels`, since a hidden `DraftPanel` has a stale rect) and the action panels' top edge is that column's top plus its `Spacer`'s height. `HFlowContainer` rather than `HBoxContainer` so an item that does not fit wraps to a second line instead of spilling left over the board. The strip is **unframed** (a `StyleBoxEmpty`, not `UiTheme.frame_stylebox` like every other panel) because its items are relic artwork, each already drawn inside its own stone rim — a frame around them frames twice.
- **Relic artwork** — `assets/relics/<id>.png`, one file per relic, the basename *is* the relic id (no mapping table). `RelicManager.relic_icon(id)` resolves and caches it, `load()`ing lazily and preferring the `.png` over the `.jpg` beside it, and returns `null` when neither is there, so the UI falls back to text — the `soul_font()` pattern. The `.jpg`s are the **sources as delivered**: 2048² art on a flat dark-teal square. The `.png`s are those with the background keyed out, and they are what the game draws — a square tile of someone else's dark teal reads as a sticker over the forest art, and the medallion's own notched silhouette and the sparkles around it are the point. The cutout was not a flat colour key: four of the thirty have a gradient or a lighter band, so a single background colour left a visible patch (worst residue 0.17 mean alpha outside the medallion). The background is estimated **per pixel** — rough mask, dilate, then a wide Gaussian of the background pixels only, normalised by the same blur of the mask — and alpha is a ramp on the distance from that estimate, with `binary_fill_holes` over the largest component so the dark linework *inside* the stone stays opaque, and the background un-multiplied out of the semi-transparent edge (`fg = (observed - bg*(1-a))/a`). That took the worst residue to 0.04. The sources stay in the repo but are kept out of the build by `exclude_filter` in `export_presets.cfg`, next to `button_source.png`. They import at 512 with `mipmaps/generate=true` in the `.import` files — 2048 is pointless VRAM for a 44px icon, and without mipmaps it aliases badly. `scripts/relic_icon.gd` (`class_name RelicIcon`) draws one with `draw_texture_rect` into the largest centred square. It first **clipped the art to a circle** (`draw_colored_polygon` with UVs) and drew a coloured ring for state; that was rejected — the art is already a round medallion, so the clip read as a second circle drawn around it. State is now tone, not geometry: a one-shot waiting to be used pulses warm (and takes the pointing hand), a spent one goes muted (opaque, never alpha), hover brightens, and the name and rule live in the instantly-opening tooltip. `RelicIcon.create()` sets `mouse_filter` itself instead of `_ready()` doing it, because the chooser card sets it to `IGNORE` so the click reaches the card — `_ready` runs on `add_child` and would overwrite that. The strip sizes its icons to **fill the column width** rather than using a fixed size (`_bar_icon_size()`): the largest that fits the current count on one row, clamped to `BAR_ICON_MIN` 44 … `BAR_ICON_MAX` 88. One row is not a preference — a second row rises into the nav buttons above — and the **worst case is 8 relics** (4 keys × `Körebe`'s 2 picks), which lands exactly on 44. So the icons shrink as relics are collected: 88 up to four, 45 at eight. In the chooser, `CARD_PAD` (30) must stay **larger than the card frame's texture margin** (26, passed to `UiTheme.frame_stylebox`), and the description's wrap width is derived from it. At the old 14 the text was laid out over the frame art's own border and ran past the card's visible edge — the same applies to the modal's own frame (margin 34, pad 40). `_fit_modal_to_screen()` is the backstop: it shrinks the three card icons by the overflow (down to `CARD_ICON_MIN`) when the box would be taller than the viewport, measured from `get_combined_minimum_size()` before the modal is shown. The worst case — the three longest descriptions — measures 892×589 against the 1400×820 design size, and `window/stretch/aspect="expand"` guarantees the viewport is never smaller than that in game units.
- One-shots come in two flavours. **Bar-activated** (`Eter Şardı`, `Ayna Tahta`, `Kılık Taşı`, `Çift Ruh` — the `RelicManager._BAR_ACTIVATED` list, `is_bar_activatable()`) render as clickable buttons in the owned list, are routed by `board_view._on_relic_activated`, and `mark_spent` on click; `board_view` holds the transient flags (`mirror_armed`, `twin_armed`) that the next placement consumes. **Contextual** — `Ruh Pazarı` only — fires from the creature panel's "Yak" button, calls `mark_spent` itself, and shows as plain faded text once spent.
- Picking a relic plays `assets/voices/relic.wav` from `_on_relic_chosen`. Like the key/lock sounds it goes through `_play_sfx_path` (a path constant, not a `preload`), so a missing or not-yet-imported file is skipped silently instead of breaking the script.
- Five relics added later need more than a `has_relic` query, so their state lives in `RelicManager` too: **Kara Gün Akçesi** keeps a piggy bank (`_piggy_*`, ticked once per tile placement from `_finalize_tile_placement`, withdrawn through `board_view.withdraw_piggy` because only board_view touches `Economy`); **Körebe** makes `relics_per_key()` 2 and `keys_are_hidden()` true, and `Board.scatter_keys()` moves uncollected keys into empty cells of rows 2–5; **İleri Görüş** is pure board_view state (`foresight_refresh_draft` + `foresight_locked_draft`). Two relics are filtered out of the chooser when they would be useless or harmful — `_can_offer()` reads a context board_view pushes in via `set_offer_context()` (money, keys left, key index) since the data layer knows neither `Economy` nor `Board`. `KOREBE_ONLY_FIRST_KEY` is a one-line balance switch.
- `Karanlık Tohum`'s "next draft has a Dagon" flag is **non-consuming** in `generate_draft()` (loss-check drafts must not eat it); `board_view` clears it with `clear_dagon_guarantee()` only after showing the real draft.

### Meta-progression (kalıcı ilerleme)

Ten lifetime thresholds (two per creature) each grant a permanent starting-soul bonus of +1, +10 in total, so a run starts with 15–25 souls. **All of it lives in `scripts/data/progression.gd`** (`class_name Progression`) — the `THRESHOLDS` table, the unlock rules and the `user://progress.cfg` persistence. It is entirely `static` (like `GameSettings`, not an autoload): the state is global and file-backed, and scene-free data classes such as `creature_scorer.gd` must be able to call it.

- Thresholds must be met **within a single run** — automatic, because the values passed to `check_threshold` are read from that run's `CreatureScorer`/`Board` state and nothing partial is ever written to disk. Reaching a higher threshold also unlocks the lower one: `check_threshold(creature, value)` unlocks every not-yet-unlocked threshold of that creature with `value <=` the reported value, and returns the new ones. Only unlocked ids are stored; the bonus is always re-summed from the table, never stored as a second source of truth.
- `creature_scorer.gd` calls `_check_progression()` right where each value is already computed, and collects what unlocked into `new_unlocks`; `board_view._flush_progression_unlocks()` drains it and shows the toast (the data layer must not touch the scene). Abzu is checked **twice** — at placement and inside `update_abzu_neighbors`, since the high neighbour counts only happen retroactively. Abzu's threshold deliberately uses `_real_filled_neighbor_count_8` (unweighted) rather than the payout count: `Derin Kaynak` doubles diagonal neighbours, and feeding that inflated number to the threshold handed out `abzu_8` to an Abzu with five real neighbours. Dagon gets the same retroactive treatment through `update_dagon_neighbors`, which both pays the difference and re-checks the threshold.
- The reward never touches the current run's money — it changes the *next* run's starting souls. `board_view._ready` logs the accrued bonus as the money log's first row, and the menu plus the progression screen show the `15 + N` breakdown.
- `scripts/scoreboard_ui.gd` (`ScoreboardPanel`) — the left-column reference table of what each creature pays at each achievement level. Its columns are the achievement measure, so each `Progression.THRESHOLDS` entry lands on exactly one cell (creature × value): green means **earned**: a cell turns `THRESHOLD_DONE_COLOR` only once its threshold is unlocked, and until then it stays `THRESHOLD_TODO_COLOR` (muted *opaque* gold) so the player can still see which values are worth chasing. A gold ring separately marks the value each creature has actually reached this run, and carry an instant tooltip naming the achievement and its `+N` permanent reward. A footer row shows the run's actual starting souls in a `SoulAmount`. The grid sits on a `UiTheme.art_backdrop` ground — the digits are small and tightly spaced, and over the bare forest art they were unreadable. `board_view._flush_progression_unlocks()` calls `refresh_thresholds(scorer.best_values)` after **every** creature placement, not only on an unlock, since the ring follows the current values; `CreatureScorer.best_values` is filled from `_check_progression`, the one place every achievement value already passes through. Each cell is wrapped in a zero-margin `PanelContainer` so the ring can be swapped in as its stylebox without changing the table's metrics.
  - `COLUMN_COUNT` is 10 because the highest threshold is `golem_10`; the table must still fit `UiTheme.COLUMN_WIDTH` (400px) or `LeftPanels` grows and the board slides off-centre, which is why the cell widths and separations are as tight as they are. Re-measure the panel's rendered width after touching any of them.
- `scripts/progression_toast.gd` (`ProgressionToast`, `CanvasLayer` 22, created by `main.gd`, ref handed to `board_view`) shows the unlock banners top-centre, stacked, each fading itself out. Both it and `CreditsPanel` cover the screen with the game's own forest art (`UiTheme.art_backdrop` with no dim) rather than a flat navy rectangle, and both hide **two** siblings in `set_open` — the backdrop and the panel — since the panel is not a child of the backdrop; hiding only the backdrop left the card floating over the menu. `scripts/progression_ui.gd` (`ProgressionPanel`, `CanvasLayer` 35) is the menu's "İlerleme" screen — it lists all ten thresholds in a two-column grid (one creature per row) on the game's forest art, marking locked ones with a muted opaque colour rather than transparency — faded text read badly — and carries a reset button that only exists in debug builds (`OS.is_debug_build()`). To wipe progress from code, call `Progression.reset_all()`.

### Turn flow (as implemented in `board_view.gd`)

1. Player clicks an expandable empty cell (`_on_cell_pressed`) → locks that cell and collects any key there. **If a key was collected, the draft is deferred**: key flight → `_advance_lock` → (4th/`Kestirme` key: lock-open linger first) → `_on_key_collected` opens the relic chooser → after the pick, `_on_relic_chosen` → `_show_draft_for_pending()`. No key → `_show_draft_for_pending()` immediately. The draft must be generated *after* the relic so draft-affecting relics apply that turn.
2. Player buys a tile from the draft (`_on_pair_selected`) → price is `pair["price"] + pending_surcharge` (`+2` only for cells reachable solely via `Çapraz Adım`; `Boşluk Deldirme` is free) or `0` (Kadim Anahtar on a key cell); with `Sabit Yön` only rotation 0 is valid and there's no rotate panel; otherwise if exactly one rotation fits it places immediately, else shows the rotate/confirm panel.
3. On placement (`_finalize_tile_placement`) → `Ayna Tahta` mirror copy, then win check (reaching `WIN_ROW`/`WIN_COL`), then creature-placement mode.
4. Player clicks a valid empty-slot cell to place the creature (`_on_creature_target_pressed`) → scores via `CreatureScorer`, pays via `Economy`; if `twin_armed` (`Çift Ruh` was activated) it re-enters creature mode once with the same type; `Ruh Pazarı` (one-shot) adds a "Yak" button (`_on_creature_burn`, +3 souls instead of placing).

Node lookups between scripts go through Godot's unique-name (`%NodeName`) system (`unique_name_in_owner` on scene nodes) rather than exported node paths — check `scenes/main.tscn` when adding new cross-node references.
